<h2 align="center">🛠️ Contexto del Problema</h2>

El proyecto aborda la problemática operativa de un minimarket local que gestiona la recepción constante de mercadería de múltiples proveedores y un flujo continuo de ventas diarias. 

**Deficiencias identificadas sin el uso de una base de datos:**
* Quiebres de stock (falta imprevista de productos esenciales).
* Descuadres diarios en el flujo de caja.
* Dificultad para rastrear las compras y pedidos realizados a proveedores.
* Retrasos en la facturación y atención en mostrador por falta de consulta centralizada de precios.

---

<h2 align="center">🎯 Objetivos</h2>

<h3 align="center">Objetivo General</h3>

Desarrollar un modelo y esquema de base de datos relacional para automatizar el control de inventario y el registro de ventas, mitigando quiebres de stock y agilizando la facturación del minimarket.

<h3 align="center">Objetivos Específicos</h3>

1. **Modelado Conceptual y Lógico:** Elaborar el Diagrama Entidad-Relación (E-R) y traducirlo al Modelo Relacional garantizando la integridad referencial y la normalización de los datos.
2. **Implementación Física:** Construir los scripts SQL (DDL y DML) para la creación de tablas, restricciones de integridad y carga de datos de prueba.
3. **Consulta y Extracción de Datos:** Formular y validar consultas complejas tanto en **Álgebra Relacional** (usando la herramienta *Relational*) como en **SQL**.
